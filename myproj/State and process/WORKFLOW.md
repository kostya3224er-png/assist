# Рабочий процесс по проекту

## Разовая настройка ChatGPT Project

1. Создать Project `Assist — разработка оверлея`.
2. Скопировать `Instructions/PROJECT-INSTRUCTIONS.md` в instructions Project.
3. Загрузить постоянные файлы: `PROJECT.md`, `ARCHITECTURE.md`, `DECISIONS.md`, `STATUS.md`, `HISTORY-SUMMARY.md`, `GLOSSARY.md` и `WORKFLOW.md`.
4. По задаче добавить соответствующие тестовые сценарии, карту базы или заметки о производительности. Не загружать API-ключи, полные логи чатов, исходные пользовательские данные или весь `node_modules`.

## Одна задача — один чат

Создавать отдельный чат внутри Project для крупной самостоятельной задачи. В сообщении указывать:

```text
Цель: какой результат нужен.
Контекст: какая функция/файл затронута.
Ограничения: что не менять и что не запускать.
Проверка: как понять, что готово.
```

Например: «Исправь восстановление кликов после hotkey minimize. Не трогай локальную базу источников. Сначала найди путь событий в main.js и renderer.js; после исправления проверь только статически, приложение не запускай».

## Обновление контекста

- После каждого завершённого изменения сверить, не устарел ли `STATUS.md`.
- В `DECISIONS.md` добавлять только устойчивые решения, которые должны пережить новые чаты.
- Архитектуру обновлять при реальном изменении кода, а не после идеи.
- Если данные не проверялись в текущем репозитории, писать «историческое» или «не подтверждено», а не стирать эту оговорку.
- Тестовые вопросы хранить отдельно от ответов в инструкции, чтобы не подгонять поведение под один пример.

## Передача файлов между ChatGPT и локальным проектом

Файлы Project в ChatGPT — это копии. Изменения в `C:\Users\Admin\Desktop\project\myproj` не появляются в Project автоматически и наоборот. После обновления документа загрузить его заново/заменить старый файл в Project. Для кодовой работы обеспечить отдельный доступ к репозиторию или приложить текущие исходники.

## Что не включать в комплект

- `.env`, API-ключи, сертификаты, голосовые записи, личные данные.
- `%APPDATA%`/`userData` `assist-data.json` целиком: там могут быть ключи, источники и история.
- `node_modules`, собранные exe и весь пользовательский контент, если задача требует только контекста проекта.

## Передача архива

`Assist-Shared-Context.zip` — короткий комплект для ChatGPT/Claude; `Assist-Codex-Reference.zip` — полный набор справок для Codex. Обычно удобнее загружать основные `.md` отдельно: их проще заменить при обновлении. Не распаковывать архивы поверх исходного приложения; это документация, не релиз программы. Подробности — `ARCHIVE-USAGE.md`.
