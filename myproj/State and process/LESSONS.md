# Уроки проекта

- Не путать пользовательское пожелание с текущей реализацией: перед техническим выводом читать свежий код.
- Не принимать предложения Claude/другого помощника как подтверждённый факт; проверять каждую причинно-следственную связь.
- Разделять retrieval, который отбирает фрагменты, и генерацию, которая формулирует ответ. Иначе непонятно, где именно промах.
- Удачный ответ на один вопрос не доказывает качество на других ролях или проектах.
- Не оптимизировать по одному времени ответа: сравнивать одинаковый набор и одновременно следить за полнотой/точностью.
- Пользовательские данные и исходники приложения — разные вещи; архив документации не должен содержать приватный профиль.
- Термины, роли и нормы должны приходить из источников/настроек пользователя, а не быть жёстко зашиты для одной игры.
- Интерфейсная диагностика полезна только если она действительно нужна пользователю; подробности держать вне обычного ответа чата.
