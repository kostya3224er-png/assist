# План проверки Assist

План содержит сценарии для ручной или автоматизированной проверки; его наличие не означает, что проверки уже запускались. Текущие тестовые материалы лежат рядом с исходниками в `tests/fixtures/`.

## AI и источники

- Точный факт и короткий запрос: нужный фрагмент передан модели, ответ верен и содержит источник.
- Переформулированный вопрос без точных слов источника: оценить попадание фрагмента отдельно от качества модели.
- Составной вопрос: подтверждённая часть отвечена, пробел по другой части обозначен явно.
- Ситуационный/RP-запрос: модель выполняет задачу в пользовательской роли и не выдаёт собственное решение за правило источника.
- Отсутствующий факт: кратко и честно указано отсутствие подтверждения.
- Отключённая тема: её содержимое не попадает в контекст AI.
- Метки `[F#]`: каждая метка соответствует фрагменту, переданному модели.
- Архив/изменения: историческое правило не выдаётся за действующее.

## Интерфейс и надёжность

- Поиск источников остаётся самостоятельным; его результат не смешивается с ответом чата.
- Пока модель отвечает, интерфейс остаётся отзывчивым; потоковый вывод проверяется для поддерживаемого провайдера.
- Ошибка API не сохраняется как обычный ответ; повторы не дублируют сообщения.
- Свернуть и развернуть оверлей мышью и биндами; затем проверить клики, поле ввода и фокус.
- Проверить микрофон, системный звук и повторное подключение аудиоустройств по отдельности.
- Сборка exe использует ожидаемую конфигурацию и не затирает данные пользователя.

## Метрики

Измерять отдельно: время локального retrieval, время первого токена/полного ответа, число API-вызовов, попадание нужного фрагмента в контекст, полноту и точность ответа. Числа вроде «150 мс», «3 секунды» и «10 секунд» — цели, пока не подтверждены повторяемыми замерами на конкретном наборе вопросов и провайдере.
