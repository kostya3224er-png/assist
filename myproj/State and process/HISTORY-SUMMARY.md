# Сжатая история проекта и пожеланий пользователя

Этот файл суммирует длительную переписку. Он не заменяет исходные сообщения, а сохраняет устойчивые требования и причины.

## Продукт и хранение

- Assist — игровой/рабочий оверлей-помощник: вопросы задаются текстом или голосом; ответ строится по пользовательским источникам и роли.
- Проект должен быть переносимым между разными играми, серверами, организациями и ролями. Пользователь меняет темы, источники, роль и стиль; правила конкретной базы не зашиваются в общую логику.
- Ранее пользователь столкнулся с различными данными `npm start` и exe, а также с ошибкой Electron `safeStorage.decryptString` при переносе шифротекста между профилями/контекстами. Поэтому перенос приложения не должен молча перезаписывать пользовательскую базу; источники/настройки и исполняемый файл — разные вещи.
- На Windows пользовательские данные Electron хранятся отдельно от каталога кода по `app.getPath('userData')`. Экспорт источников JSON — безопаснее для переноса базы, но не эквивалент полного профиля с API-ключами и историей.

## Интерфейс и оверлей

- Верхний поиск по включённым источникам должен оставаться самостоятельным, без участия модели.
- Чат нужен для короткого понятного ответа, а не для вывода фрагментов, счётчиков и отладочных блоков.
- Пользователь многократно сообщал, что оверлей не должен останавливать/забирать фокус игры. Также был баг: после сворачивания/разворачивания биндом UI переставал реагировать; визуально восстановление через кнопку выглядело плавнее.
- Голос использует микрофон, системный звук или оба канала; выбран Yandex SpeechKit как основной распознаватель. Были ошибки захвата системного аудио и распознавания, когда текст распознался, но вопрос не отправился.
- Stream proof, горячие клавиши, переключение курсора, темы, настройки аудио и история — важные существующие функции, не убирать без отдельного запроса.

## Качество AI и поиск

- ИИ должен быстро просматривать выбранные источники, учитывать перефраз, ранги/числа/команды и отвечать на все части вопроса.
- Ролевые задания требуют логичной физической последовательности и самостоятельного выполнения в заданной роли; отсутствие пошагового правила в источнике не повод отказываться от сцены.
- Одновременно нельзя выдумывать игровые нормы или использовать выключенные источники. Для нормы важны действующий статус, точный пункт, исключения и дата.
- Архивы/журналы изменений не должны перебивать актуальное правило; старое наказание нельзя выдавать как текущее.
- В прошлых обсуждениях предлагались RAG, семантические embeddings, словари, карточки фактов, кэш и reranker. Владелец просил упростить UI, убрать словари/карточки из виду и минимизировать запросы. Идеи не являются реализованными функциями, пока это не подтверждено кодом.
- Поиск самостоятельной строки работает; пользователь отдельно просил не переделывать его. Проблемы в ответах надо разбирать по причине: нужный фрагмент не найден, найден не тот, модель проигнорировала, данных реально нет, или в контекст попала устаревшая норма.

## Скорость и API

- Пользователь просил сделать ответы быстрыми, ориентир — около 3 секунд в удачных случаях и не более 10 секунд как желаемый опыт, но позже отдельно уточнил, что нельзя обрывать нормальный ответ жёстким таймером из-за длины размышления.
- Время полного ответа должно быть видно в шапке оверлея; миллисекунды и найденные блоки не добавлять в чат.
- Нормальный путь должен избегать дополнительных запросов модели; короткие retries по ошибкам API — отдельный механизм.
- Ошибки 503/429, audio decode, перенос encrypted API keys и перезапуск после сворачивания возникали в разных версиях; считать их историей, пока они не воспроизведены в текущей сборке.

## Принцип работы с проектом

- Сначала прочитать текущий код и документацию, не начинать с нуля.
- Не добавлять вспомогательный интерфейс или «умные» слои без ясной пользы.
- Не запускать приложение, когда пользователь прямо просит не запускать; при запросе «сделай exe» собирать, но не менять код без необходимости.
- При неопределённости продолжать независимую работу и явно отделять факт от предположения.
